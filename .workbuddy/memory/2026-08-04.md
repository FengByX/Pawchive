### 报告遗漏、我额外发现的问题
1. **Cloudflare 自愈重试从未生效**（比报告的 P1 更严重）
   `ApiClient.buildOkHttpClient()` 拦截器顺序为 `memoryCache → cloudflare → cloudflareRetry → logger`。
   retry 在 cloudflare 注入**之后**，其 `chain.proceed()` 不会重新经过注入逻辑，
   `request.newBuilder().build()` 复制的是带**旧 cf_clearance** 的请求 → 刷新出的新凭据根本没用上。
   代码注释"cloudflareInterceptor 会自动注入新 Cookie"是错的。
   修法：把 retry 拦截器注册到 cloudflare 拦截器**之前**。

2. **`CloudflareManager.isSolving` 并发语义有缺陷**（CloudflareManager.kt:159）
   已有过盾任务在跑时，后来者不是等待共享结果，而是立刻 `cont.resume(hasClearance())` 返回 false。
   并发图片加载遇 403 会集体失败，而不是复用那一次过盾。应改为单飞（single-flight）共享同一个 Deferred。

3. **`runBlocking` / `GlobalScope` 面积比报告大**，共 5 处：
   - `SettingsManager.kt:87` — `read()` **每次读取都 runBlocking**（最糟）；
     且 `MainActivity.attachBaseContext:36` 就构造 SettingsManager → 每次 Activity 启动主线程阻塞读盘，冷启动直接受影响
   - `UpdateChecker.kt:47`、`BlockedCreatorManager.kt:28` — 构造期阻塞 + GlobalScope 落盘
   - `BookmarkManager.kt:27/141`、`SearchHistoryManager.kt:24/69` — 同上

4. **`BookmarkManager` 被 new 了 4 次，各持独立内存缓存快照**
   HomeFragment:66 / CreatorProfileFragment:76 / PostDetailFragment:94 / SearchFragment:88。
   `editSync` 只更新自己那份 cache → 详情页收藏后回列表看不到变化，是用户可见的串屏 bug。
   `BlockedCreatorManager` 已是单例，这两个应对齐。

5. **API 内存缓存无上限、过期项永不回收**
   `apiMemoryCache` 只写不清，信息流翻页会让 JSON body 字节数组单调堆积到进程结束。

6. **P0 定性补强**
   `memoryCacheInterceptor` 注册在 `authApi()` 通过 `newBuilder()` 追加的 `cookieInterceptor` **之前**，
   查缓存时请求上还没有 session 头，key 天然不可能带账号维度；且 `publicApi` 与 `authApi` 共用同一个 map。
   即匿名与登录态是同一个缓存命名空间——是确定发生，不是"可能"。

### 已应用的修复（代码已改，Kotlin 编译通过；dex 打包遇环境文件锁待复验）
1. **ApiClient.kt**
   - P0 缓存跨用户泄露：缓存 key 加入账号命名空间（`u:<session>` / `public`），`currentSessionCookie` 在 `authApi()` 设定、`clearMemoryCache()` 重置；public/auth 共用 map 但按 namespace 隔离。
   - P1 403 失败路径：原 `response.close()` 后再 `newBuilder()` 返回关闭流。改为失败分支用 `Response.Builder()` 构造全新 403 占位响应（带 `EMPTY_RESPONSE_BODY`），不再依赖已关闭响应体。
   - P1 网络拦截器 `runBlocking` 过盾：`clearanceMutex` 串行化 `ensureClearance`，避免并发 403 多线程同时驱动 WebView（理想修复是异步 WebView，需设备验证，暂未做）。
   - 补充①：拦截器顺序调整为 `memoryCache → cloudflareRetry → cloudflare → logger`，并用 `X-CF-Retry` 头防重入，自愈重试现在能注入新 Cookie。
   - 补充③：新增 `putCache()`，落盘前回收过期项 + 容量上限 200 淘汰最旧，内存缓存不再无限增长。
   - P2 刷新：`getRecentPosts` 增加 `@Header("Cache-Control")` 入参，`HomeViewModel.refresh()` 传 `no-cache` 绕缓存；`AuthRepository.logout()` 调 `ApiClient.clearMemoryCache()`。
2. **AuthRepository.kt**：`logout()` 调 `ApiClient.clearMemoryCache()`，清内存缓存 + 重置 authApi 实例与 session。
3. **SearchHistoryManager / BookmarkManager / BlockedCreatorManager**：构造期 `runBlocking` 改为 IO 线程 `init` 异步加载（不再阻塞主线程）；落盘从 `GlobalScope` 换成受控 `ioScope(SupervisorJob + Dispatchers.IO)` + `Mutex` 串行 + `runCatching` 异常处理；加 `ensureLoaded()` 护栏防止"缓存未加载时基于空缓存写入导致旧数据丢失"。
4. **SettingsManager.kt**：`read()` 不再每次 `runBlocking`，改为读内存快照 `settingsCache`（构造时异步加载）；`write()` 改 `ioScope` 异步落盘。
5. **UpdateChecker.kt**：构造期 `runBlocking` 改 `init` 异步加载；`recordCheckTime()` 的 `GlobalScope` 改 `ioScope`。
